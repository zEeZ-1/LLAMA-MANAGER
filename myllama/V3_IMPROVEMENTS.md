# myllama_v3 相对原版 llama.cpp 的修改与作用

对比基线为 v3 发布清单指定的上游提交 `9214bdb554544c35e4a9e2c2e8b75d8cfee330ab`。改动覆盖分布式调度、RPC 传输、内存管理、Orin 算子适配和启动策略。

## 分布式预填充

### 有界微批次流水线

**修改：** 增加 `--rpc-prefill-schedule`、`--rpc-prefill-window` 及对应配置接口。将微批次的图准备与执行分离，把长提示拆成多个微批次，为窗口中的微批次保留独立计算图与输入，通过设备队列组织跨节点执行。同一设备按 token 块顺序处理，只有上游数据可见后才允许下游消费。

**作用：** 让不同设备处理不同微批次，减少整条设备链逐块串行推进时的空闲等待；限制在途微批次数量，防止无限制提交挤占内存。

该路径面向单序列、完整 GPU 卸载、按层切分的新文本提示。需要中间状态输出、已有序列缓存或不满足图结构约束的请求使用兼容调度；MTP 状态传递也受这些条件约束。

### 边界张量异步中转与输入上传

**修改：** 对符合条件的 RPC 与本机 CUDA 相邻分段，分配有界的主机中转缓冲。计算完成后发起边界张量读取，通过事件通知后续设备上传和执行；优先推进已具备输入的下游任务。符合条件的主机连续输入使用异步上传，已中转的输入避免重复拷贝。

**作用：** 把部分数据传输与其他设备的计算交叠，减少控制端同步等待和重复搬运，同时确保缓冲区在读取完成前不会被覆盖。

### 计算缓冲复用与失败回退

**修改：** 较大窗口在设备执行顺序和边界数据保存受到约束的前提下，共享可复用的加速器计算缓冲；主机输入与传输副本保持独立。为共享缓冲增加引用计数。图准备或分配失败时，先处理已经准备的微批次，再转回兼容调度，避免重复应用循环状态；新序列流水线失败时清理其缓存状态。

**作用：** 控制增加在途微批次所带来的额外内存需求，防止共享缓冲提前释放、输入互相覆盖以及失败后的状态残留。

### 分布式预热

**修改：** 扩展原有预热流程：启用分布式预填充时，在服务就绪前用模型词表构造合成 token 和文本，覆盖较大的预填充图及文本处理路径。预热后清理 KV 与循环状态。

**作用：** 将部分图构建、设备分配和文本处理初始化开销前移，减轻首次正式请求的冷启动影响，同时隔离预热内容与正式会话。

## RPC 通信与内存申请

### 因果掩码按行编码

**修改：** 为 RPC 增加掩码编码能力协商。对每行由零前缀和负无穷后缀组成的连续浮点掩码，先校验实际位模式，再只传输各行前缀长度，由远端恢复完整张量。增加格式、形状、大小及目标缓冲区边界检查；不满足条件时使用普通张量传输。

**作用：** 减少长提示因果掩码的网络载荷；对符合编码条件的掩码保持恢复后的位模式一致，并保留与不支持该编码的 worker 协作的路径。

### 接收与设备写入分离

**修改：** 将 RPC `SET_TENSOR` 的同步点从接收数据前，后移至写入设备前。接收、缓存处理或掩码解码可先在主机侧进行，真正写入设备之前再等待此前计算完成。

**作用：** 给网络接收与前一段设备计算留下重叠机会，减少过早同步造成的等待，并维持设备读写顺序。

### 远端缓冲分组上限

**修改：** 增加 `GGML_RPC_BUFFER_MAX_MIB`，限制 RPC 后端用于缓冲区分组的最大申请规模，保持单个张量完整；发布启动环境统一设置该上限。

**作用：** 降低共享内存设备在模型加载时申请超大连续设备缓冲区的压力。该限制约束分配分组，不代表模型总内存或 KV 总容量下降。

## Orin CUDA 算子适配

| 修改 | 作用及生效条件 |
| --- | --- |
| **量化矩阵向量乘分发**：`overlay-hybrid.so` 为符合形状与连续性条件的 Q4_K、Q6_K 单列计算选择多行处理内核，并为目标输出头使用独立分发。 | 调整解码阶段的行处理粒度，使目标计算更贴合 Orin 的执行资源；不符合条件的调用交给原 CUDA 库。 |
| **量化矩阵乘布局**：`mmq-fused.so` 为匹配形状的 Q4_K、Q6_K 矩阵乘选择定制分块与共享内存布局。 | 调整预填充相关矩阵乘的线程组织和片内数据布局，针对目标形状改善资源使用；其余调用保持原有分发。 |
| **MoE gate/up 专用入口**：`moe-mmq-tiles.so` 为 Orin 上匹配的 IQ3_S 专家矩阵形状提供带 gate/up 融合参数的 MMQ 分发，按调度器选定的块宽调用对应内核。 | 让目标专家计算能够进入定制分发路径，并保留不匹配形状的回退入口。 |
| **权重 L2 预取**：`l2-hint.so` 在符合对齐、形状及融合条件的 Q4_K gate/up 路径中，提前发出后续权重块的 L2 预取提示。 | 尝试用当前计算覆盖后续权重访问的部分等待；作用范围由量化类型和内核形状共同决定。 |
| **GDN 的 Orin MMA 入口**：为符合条件的 Gated Delta Net 计算增加 Orin 专用选择分支，通过 `MYLLAMA_GDN_ORIN_WIDTH` 选择分块路径，并检查设备共享内存资源。 | 允许目标循环状态计算使用已有的 MMA 内核组织；需要显式配置该开关，发布启动脚本没有默认启用它。 |
| **循环卷积输入重排与拼接**：增加共享内存分块内核，把 token-major QKV 转为卷积需要的 channel-major 排布，同时拼接历史状态前缀。 | 针对匹配布局改善数据搬运方式；由 `MYLLAMA_GDN_CONV_TILE` 显式启用，发布启动脚本没有默认启用它，其他布局沿用通用拼接。 |

前四项由发布启动环境统一加载定制动态库；具体算子是否命中专用路径仍取决于类型、形状和调用参数。GDN 与卷积输入处理的修改集成在包内 CUDA 库，对应源码保存在 v3 的 `source/`。

## 启动与设备放置

**修改：** 将分布式设备顺序固定为首端 RPC、本机 CUDA、末端 RPC，显式把 embedding 放在首端，并为 MTP 开启和关闭提供不同层分配。MTP 配置将输出相关层与 MTP 头安排到末端设备；默认启动策略关闭 MTP、启用预填充流水线。主控和 worker 统一使用包内库路径、算子覆盖及 RPC 缓冲限制，允许通过环境变量覆盖模型、地址和端口。

**作用：** 把设备放置、预填充方式和可选 MTP 组织成一致的部署策略，使紧密关联的计算尽量保持在同一设备，减少手工组合参数时的配置偏差，并确保两端采用同一套运行时组件。

## 调度可观测性与回归保护

**修改：** 增加流水线准入、图分段提交和输入上传的可选跟踪；增加队列顺序、背压、取消、迟到事件、掩码编解码及窗口计算的回归检查。

**作用：** 便于定位分布式执行中的等待环节，并为调度顺序、数据恢复和窗口执行行为提供回归保护。
